# Назначение администратора

Команды выполняйте из `backend/` после применения миграций.
Сначала зарегистрируйте аккаунт обычным способом. Затем:

```sh
go run ./cmd/admin grant --email admin@example.com
```

Команда использует `DATABASE_URL` и текущие правила загрузки окружения.
Email нормализуется; аккаунт должен существовать. Повторное назначение успешно.
Для изолированных проверок используйте `APP_ENV=test` и `DATABASE_URL`
именно временной тестовой БД, а не development-базы.

Обновите страницу приложения: в меню пользователя появится «Админка».
Прямой адрес — `/admin/users`; повторный вход не требуется.

Если команда сообщает `user not found`, проверьте email и целевую БД.
Если БД не содержит столбца роли, выполните `go run ./cmd/migrate up`
перед запуском обновлённого API.

Удаление через админку удаляет обычный аккаунт вместе с мониторами и сессиями
без возможности восстановления. Административные аккаунты защищены.
Правила изменения поведения — в [контракте администрирования](../../rules/backend/administration.md).
