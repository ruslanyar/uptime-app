# Изменения профиля и аватаров

Маршруты и общая защита — в [HTTP-контракте](../../backend/README.md#http-контракт).

- Меняйте профиль только владельца access token; не изменяйте email или пароль
  через этот маршрут. Требуйте имя: trim и 2–50 Unicode-символов.
- JSON допускает `name` и необязательный boolean `remove_avatar`;
  multipart — ровно одно поле `name` и один файл `avatar`. Другие поля отклоняйте.
  Без `remove_avatar: true` JSON должен сохранять текущий аватар.
- Проверяйте содержимое декодированием, не расширение или MIME-заголовок.
  Допускайте JPEG, PNG, WebP, GIF; лимит — 512 000 байт и 16 миллионов пикселей.
  Невалидный или слишком большой файл — `400 invalid_request`;
  multipart больше лимита файла плюс 16 KiB — `413 file_too_large`.
- Имя и изменение аватара сохраняйте вместе. При ошибке обновления БД удаляйте
  новый файл и сохраняйте прежний; прежний файл удаляйте только после успеха.
  Повторное удаление аватара должно быть допустимым.
- `avatar_url` возвращайте как путь относительно origin API;
  при отсутствии аватара опускайте поле.
- Используйте случайные имена файлов. Не выдавайте листинг, произвольные пути
  и файлы. При замене меняйте URL, сохраняя immutable-кеширование изображения.

## Хранилище

`AVATAR_DIR` задаёт каталог относительно рабочего каталога API,
по умолчанию `uploads/avatars`.

- Обеспечивайте запись для процесса API, сохранность между перезапусками
  и резервное копирование вместе с БД.
- Для нескольких экземпляров API используйте общий каталог.
- `backend/uploads/` исключён из Git; для другого пути настройте исключение.
