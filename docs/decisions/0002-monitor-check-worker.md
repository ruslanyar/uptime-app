# ADR 0002: фоновая проверка сайтов с арендой в PostgreSQL

- Статус: Принято
- Дата: 2026-10-13

## Контекст

Проверки должны работать без браузера, переживать перезапуск API и не записывать
результаты удалённой или изменённой конфигурации. Проект уже использует PostgreSQL
и единый Go API; отдельной очереди и инфраструктуры обработчиков нет.

## Рассмотренные варианты

Проверки из браузера, отдельный сервис с внешней очередью и обработчик внутри API
с расписанием в PostgreSQL. Браузер не обеспечивает непрерывность; отдельный сервис
добавляет операционные зависимости для первой версии.

## Решение

Запускать ограниченный обработчик в процессе API. Хранить расписание и последний
результат у монитора. Использовать атомарный захват `FOR UPDATE SKIP LOCKED`
с токеном и сроком аренды; проверять вне транзакции и условно записывать результат.
Любое сохранение конфигурации аннулирует аренду.

## Последствия

Несколько API могут делить очередь без внешнего брокера. После остановки задания
возвращаются в очередь по истечении аренды; строгая однократность HTTP-запроса
не гарантируется при истечении аренды, но старый результат не принимается.
API должен работать постоянно; недоступность всех процессов останавливает проверки.
Число одновременных запросов ограничено на процесс, а не на весь кластер.

Отдельная миграция обязательна до запуска новой версии. Обработчик завершается
до закрытия БД. Историю проверок и уведомления следует проектировать отдельно,
не выводить процент доступности из единственного последнего результата.
