# ADR 0001: роль администратора в PostgreSQL

- Статус: Принято
- Дата: 2026-10-13

## Контекст

Просмотр и удаление зарегистрированных пользователей требуют отдельного права,
но приложение уже имеет cookie/Bearer авторизацию и пользовательские аккаунты.

## Рассмотренные варианты

Роль аккаунта в БД, список email в конфигурации сервера и отдельный вход
для администраторов. Пользователь выбрал роль аккаунта в БД.

## Решение

Использовать роли `user | admin` и текущий вход. Администратора назначать
операторской командой существующему аккаунту; публичные формы роль не меняют.
На каждом административном запросе читать текущую роль из PostgreSQL.

## Последствия

JWT не хранит административные права; назначение действует без повторного входа.
Применение миграции обязательно до запуска API. Удаление защищает всех
администраторов, включая инициатора; проверка роли цели и удаление сериализуются
с назначением роли через блокировку строки.
