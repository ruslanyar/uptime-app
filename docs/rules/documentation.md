# Правила документации

## Размещение

| Раздел            | Когда использовать                                                      |
| ----------------- | ----------------------------------------------------------------------- |
| `docs/guides/`    | Процедура: подготовка, команды, проверка результата, устранение ошибок. |
| `docs/rules/`     | Действующие ограничения, контракты и требования к изменениям.           |
| `docs/templates/` | Заготовка задачи, плана или ADR; без данных конкретной задачи.          |
| `docs/decisions/` | ADR: контекст, принятое архитектурное решение и его последствия.        |
| `docs/tmp/plans/` | Локальный план, разработанный с пользователем в Plan mode.              |
| `docs/tmp/tasks/` | Локальные требования, заметки и прогресс конкретной задачи.             |

README репозитория и проектов сохраняйте точками входа для запуска и проверок.
AGENTS.md содержит обязательные инструкции агенту и ссылки на подробности.
Для правил и гайдов отдельного проекта используйте вложенный каталог
`backend/` или `frontend/`; общие документы размещайте в корне раздела.

## Содержание и ссылки

- Указывайте рабочий каталог для команд, необходимые условия и критерий успеха.
- Храните контракт или правило в одном месте; из других документов давайте ссылку.
- Версии и значения конфигурации берите из кода и конфигурационных файлов.
  Не составляйте отдельные перечни зависимостей или возможностей приложения.
- При переносе документа обновляйте входящие и исходящие ссылки, включая
  README и AGENTS.md. Новые постоянные документы добавляйте в [индекс](../README.md).
- Обновляйте документацию вместе с изменением поведения; завершённые тестовые
  отчёты и историю работ не добавляйте в постоянные документы.

## Рабочие файлы

`docs/tmp/` целиком исключён из Git. Создавайте каталоги по необходимости;
не используйте `git add -f` для рабочих файлов и не добавляйте ссылки на них
из README или постоянной документации.

Файлы задач создавайте по [шаблону](../templates/task.md), когда нужно сохранить
требования и прогресс локально. Планы сохраняйте по [шаблону](../templates/plan.md)
только после совместной разработки в Plan mode; в Default mode файлы планов
не создавайте. Используйте понятные имена вида `<task-name>.md`.

До завершения задачи перенесите необходимые команды, контракты и ограничения
в README, гайды или правила, а архитектурные решения — в ADR.
Рабочие файлы после этого можно удалить без потери проектных инструкций.

## Архитектурные решения

Создавайте ADR для решений, которые задают долговременные ограничения на
архитектуру, хранение данных, безопасность или взаимодействие компонентов.
Обычные переносы файлов, исправления и отчёты о выполнении задач ADR не требуют.

- Используйте [шаблон ADR](../templates/adr.md) и следующий свободный номер:
  `docs/decisions/NNNN-short-name.md`, начиная с `0001`.
- Записывайте статус: `Предложено`, `Принято`, `Отклонено` или `Заменено`.
  Предложение не становится действующим правилом до принятия.
- Для принятого решения указывайте дату, контекст, рассмотренные варианты,
  выбранное решение и последствия для следующих изменений.
- Действующие требования фиксируйте в правилах и связывайте с ADR ссылкой.
  Не восстанавливайте решения из старых планов без проверки их актуальности.
- При замене принятого решения добавляйте новый ADR; старому меняйте статус
  на `Заменено` и добавляйте ссылку на новый, сохраняя прежний контекст.
- Добавляйте ADR в [индекс решений](../decisions/README.md).
