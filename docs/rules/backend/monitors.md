# Изменения мониторов

Маршруты, форматы ответов и общая защита — в
[HTTP-контракте](../../../backend/README.md#http-контракт).

- Для создания и редактирования требуйте `url` и `interval_seconds`.
  Интервал — целое число от 60 до 86 400 секунд включительно.
- URL обрезайте по краям, но не нормализуйте регистр, путь или порт.
  Сохраняйте лимит 2 048 байт, HTTP(S), обязательный hostname и порт 1–65 535,
  если указан. Запрещайте credentials, fragment и внутренние пробельные символы.
  Пути, query, localhost и IP-адреса остаются допустимыми.
- Определяйте владельца по access token, не по запросу. Все выборки и изменения
  ограничивайте владельцем. Чужая и отсутствующая запись при PUT/DELETE —
  одинаковый `404 monitor_not_found`, в том числе при повторном удалении.
- Точный повтор URL одного владельца возвращайте как `409 monitor_conflict`,
  независимо от интервала; обеспечивайте это и при конкурентных запросах.
  Одинаковые URL разных владельцев допускаются.
- Сохраняйте `created_at` при редактировании; `updated_at` меняйте временем
  PostgreSQL при каждом успешном сохранении, даже без изменения значений.
  При создании оба времени равны; в ответах используйте UTC.
- Список сортируйте по `created_at DESC, id DESC`, пустой список возвращайте
  как массив `[]`, не `null`.
- Сохраняйте последнее успешное изменение при конкурентном редактировании.
  Ошибка валидации, конфликт или отсутствие записи не должны менять монитор.
- Неверный UUID и некорректные данные возвращайте как `400 invalid_request`.
  Не вводите автоматический повтор изменяющих запросов после сетевой ошибки:
  результат может быть неизвестен.

- Фавиконки загружайте отдельно от сохранения монитора через
  `GET /monitors/favicon?url=...` с access token. Проверяйте URL по правилам
  монитора; отсутствие или ошибка загрузки иконки возвращает `204`.
  Ищите HTML-ссылки `icon` и `apple-touch-icon`, учитывая относительные пути,
  первый допустимый `<base>` и конечный URL после редиректа;
  затем проверяйте `/favicon.ico`.
  `<base>` без атрибута `href` пропускайте; явно заданный `href=""`
  разрешайте относительно URL страницы и учитывайте при выборе первого
  допустимого base. Последующие base не должны заменять выбранный URL.
  Конечный URL сохраняйте и при ошибке статуса или чтения HTML, чтобы
  `/favicon.ico` запрашивался у сайта назначения.
- При загрузке фавиконок разрешайте только публичные HTTP(S)-адреса.
  Проверяйте все DNS-адреса перед соединением и подключайтесь к проверенному IP;
  применяйте защиту к каждой иконке и каждому редиректу. Не пересылайте cookies,
  токены пользователя или переменные HTTP proxy внешнему сайту.
- Ограничивайте загрузку фавиконки пятью секундами, префикс HTML для поиска —
  512 КиБ, каждое изображение — 512 КиБ, редиректы — двумя переходами,
  HTML-кандидаты — шестью ссылками.
  Разбирайте прочитанный префикс HTML и при превышении полного размера страницы;
  не дочитывайте остаток. Ссылки за пределами префикса не участвуют в поиске.
  Для изображений читайте не более лимита плюс один байт, чтобы обнаружить
  превышение и отклонить файл целиком, даже если его префикс декодируется.
  DNS и все попытки подключения для HTML, иконок и редиректов должны делить
  оставшийся бюджет Resolve и учитывать более ранний deadline вызывающего кода.
  Каждое подключение ограничивайте двумя секундами в пределах этого бюджета.
  Передавайте исходную отмену и deadline в DialContext явно: Go Transport
  снимает их с контекста запроса, сохраняя его значения. При отмене прекращайте
  начатые DNS/подключения и не начинайте следующие попытки.
  Сигнатура изображения сама по себе не подтверждает пригодность кандидата:
  при повреждении продолжайте поиск следующей ссылки, затем `/favicon.ico`.
  PNG, JPEG и статический WebP проверяйте декодированием после проверки размеров;
  GIF и анимированный WebP — декодированием всех кадров после проверки числа
  кадров и суммарных пикселей. Для WebP проверяйте полноту RIFF-контейнера
  и расположение кадров в пределах холста.
  ICO проверяйте во всех представлениях: вложенные PNG декодируйте, у DIB
  проверяйте размеры, палитру, битовые маски и полноту цветовых строк и маски
  прозрачности. Поддерживайте PNG и несжатые DIB с заголовками 40/108/124 байта,
  глубиной 1/4/8/16/24/32 бита, а также BI_BITFIELDS для 16/32 бит;
  неподдерживаемые варианты считайте недоступными.
  До декодирования ограничивайте стороны растрового изображения 2 048 пикселями,
  число пикселей — 1 048 576; для GIF, WebP и ICO применяйте этот лимит к сумме кадров
  и ограничивайте число кадров 64. Проверка содержимого использует оставшийся
  бюджет Resolve: учитывайте отмену при чтении декодером и после декодирования,
  не запускайте фоновых декодеров, продолжающих работу после возврата.
  SVG проверяйте как полный XML-документ с единственным корнем в SVG namespace,
  корректными пространствами имён и без DTD; ограничивайте глубину 128,
  число XML-токенов 16 384 и число пространств имён в области видимости 64.
  Явные размеры SVG ограничивайте теми же пределами сторон и площади;
  допускайте безразмерные значения, px/pt/pc/mm/cm/in/em/ex и проценты.
  Проверка SVG не заменяет браузерный рендеринг геометрии, CSS и ссылок:
  сохраняйте `rasterizeIcon` для выдачи интерфейсу только PNG-пикселей и глобус
  при оставшейся ошибке браузерного декодирования. Если пригодных кандидатов
  нет, сохраняйте `204` и глобус.
  Возвращайте только изображения PNG, JPEG, GIF, WebP, ICO и SVG с `no-store`,
  `nosniff` и CSP sandbox. Не сохраняйте иконки в БД.

## Проверки доступности

- Выполняйте GET с сервера при закрытом браузере. После не более пяти редиректов
  только конечный HTTP 200–299 означает `up`; остальные HTTP-коды и сетевые
  ошибки сразу означают `down`. Таймаут всей проверки — десять секунд.
  Проверяйте TLS-сертификат; тело конечного ответа не читайте.
- Используйте общий `internal/publichttp` для проверок и фавиконок: каждый DNS-ответ
  и адрес подключения должен быть публичным; подключайтесь к проверенному IP.
  Ограничивайте отдельное подключение и TLS handshake двумя секундами,
  заголовки ответа — 64 КиБ. Применяйте ограничения при каждом редиректе;
  не пересылайте cookies, Authorization, Referer или environment proxy.
  Эти ограничения не должны ослабляться для тестов или локального запуска.
- Внутренние URL сохраняйте по прежним правилам, но выдавайте `blocked`
  с `blocked_address` без подключения к внутреннему адресу.
  Адрес может стать запрещённым при DNS-разрешении или после редиректа.
- Возвращайте в `Monitor.monitoring` поля `status` (`unknown | up | down | blocked`),
  `last_check` (объект или `null`), `next_check_at` (UTC) и `is_stale`.
  `last_check` содержит `checked_at` (UTC), `http_status`, `response_time_ms`,
  `error_code`; последние три поля допускают `null` и всегда присутствуют.
- `response_time_ms` измеряйте до получения заголовков конечного ответа,
  включая DNS, соединение, TLS и редиректы; это не время полной загрузки страницы.
  При получении конечного ответа сохраняйте HTTP-код и время ответа;
  при ошибке до конечного ответа оба поля — `null`.
  Коды ошибок: `http_status`, `dns`, `connection`, `tls`, `timeout`,
  `redirect`, `blocked_address`, `network`. Не выдавайте сырые сетевые ошибки.
- Первая проверка — сразу после создания; существующие записи после миграции
  тоже готовы к проверке. Следующая — через сохранённый интервал после записи
  результата. После простоя не воспроизводите пропущенные проверки.
- При любом сохранении назначайте проверку сразу и аннулируйте аренду.
  Изменение URL очищает результат до `unknown`; при том же URL сохраняйте результат.
  Проверки не меняют `updated_at`, который описывает только конфигурацию.
- Обработчик в каждом процессе API проверяет очередь раз в секунду, выполняет
  максимум десять проверок одновременно. Забирайте задания атомарно через
  `FOR UPDATE SKIP LOCKED`, аренда — тридцать секунд с уникальным токеном.
  Не держите транзакцию во время HTTP-запроса. Результат принимается только
  с действующим токеном неистёкшей аренды; удалённые и изменённые записи
  не должны получать старый результат.
- Ошибки PostgreSQL и отмену при остановке API не записывайте как сбой сайта.
  Операции хранилища ограничивайте пятью секундами, после ошибок приостановите
  выдачу заданий на пять секунд. Незавершённая аренда должна истечь.
  При остановке отменяйте сетевую работу и дождитесь обработчика до закрытия БД.
- Для имеющегося результата вычисляйте `is_stale`, когда `next_check_at`
  просрочен более чем на тридцать секунд; сохранённый `status` не меняйте.
  Без первого результата оставляйте `unknown` и `is_stale=false`.
- В интерфейсе показывайте текстовый статус вместе с цветом, HTTP-код/причину,
  время ответа при наличии и дату проверки. Устаревшие результаты показывайте
  нейтрально с пометкой и последним известным состоянием.
  Обновляйте список раз в пятнадцать секунд в видимой вкладке и при возвращении;
  сохраняйте карточки, редактор и фокус. Отменяйте запросы при уходе, скрытии
  вкладки и изменении данных; игнорируйте их поздние результаты.
  Ошибка загрузки списка не меняет доступность сайтов.

Архитектура обработчика и аренды — в [ADR 0002](../../decisions/0002-monitor-check-worker.md),
запуск и диагностика — в [гайде мониторинга](../../guides/backend/monitoring.md).
