# Изменения мониторов

Маршруты, форматы ответов и общая защита — в
[HTTP-контракте](../../../backend/README.md#http-контракт).

- Для создания и редактирования требуйте `url` и `interval_seconds`.
  Интервал — целое число от 60 до 86 400 секунд включительно.
- URL обрезайте по краям, но не нормализуйте регистр, путь или порт.
  Сохраняйте лимит 2 048 байт, HTTP(S), обязательный hostname и порт 1–65 535,
  если указан. Запрещайте credentials, fragment и внутренние пробельные символы.
  Пути, query, localhost и IP-адреса остаются допустимыми.
- Определяйте владельца по access token, не по запросу. Все выборки и изменения
  ограничивайте владельцем. Чужая и отсутствующая запись при PUT/DELETE —
  одинаковый `404 monitor_not_found`, в том числе при повторном удалении.
- Точный повтор URL одного владельца возвращайте как `409 monitor_conflict`,
  независимо от интервала; обеспечивайте это и при конкурентных запросах.
  Одинаковые URL разных владельцев допускаются.
- Сохраняйте `created_at` при редактировании; `updated_at` меняйте временем
  PostgreSQL при каждом успешном сохранении, даже без изменения значений.
  При создании оба времени равны; в ответах используйте UTC.
- Список сортируйте по `created_at DESC, id DESC`, пустой список возвращайте
  как массив `[]`, не `null`.
- Сохраняйте последнее успешное изменение при конкурентном редактировании.
  Ошибка валидации, конфликт или отсутствие записи не должны менять монитор.
- Неверный UUID и некорректные данные возвращайте как `400 invalid_request`.
  Не вводите автоматический повтор изменяющих запросов после сетевой ошибки:
  результат может быть неизвестен.
