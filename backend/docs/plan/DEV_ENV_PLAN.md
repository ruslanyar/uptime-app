# Единый запуск development-окружения

## Реализация

Из корня репозитория `npm run dev` вызывает `scripts/dev.sh`.
Корневой package.json приватный, без зависимостей и npm workspaces.
`npm run db:up` и `npm run db:stop` отдельно управляют service `postgres`
из `backend/compose.yaml`.

Скрипт проверяет инструменты, Docker daemon, свободные порты и блокировку
повторного запуска. При первом запуске, отсутствии node_modules или изменении
package.json/package-lock.json выполняет frontend `npm ci`. Собирает API и
мигратор, поднимает постоянную PostgreSQL и применяет миграции. Затем запускает
API и Next dev, проверяет `/api/v1/auth/me` (401 без cookies) и `/login` (200).

Адреса — `http://localhost:3000` и `http://localhost:8080`; приложения слушают
только loopback. Cookies — Secure=false, SameSite=lax. JWT-секрет создаётся один
раз с правами 600 в игнорируемой `.dev/`; директория имеет права 700. Там же
хранятся бинарники, fingerprint зависимостей и блокировка launcher. Пользовательские
.env не изменяются. Контракт API и приложение остаются прежними.

Ctrl+C/SIGTERM и ошибки завершают собственные группы процессов с дочерними;
после 15 секунд оставшиеся процессы завершаются принудительно. PostgreSQL
останавливается только если скрипт её запустил. Данные volume сохраняются.
Go-код пересобирается при перезапуске; Next dev обновляет фронтенд автоматически.

## Приёмка — 2026-10-06

Проверено на Linux, Bash 5.2, Node.js 24.21 и Go 1.27.1:

- Первый `npm run dev`: установка frontend-зависимостей, сборка, PostgreSQL,
  миграции и готовность обоих приложений.
- Повторный запуск пропускает установку неизменившихся зависимостей.
- В Chrome: регистрация, аккаунт, refresh, перезагрузка, выход и вход.
- После перезапуска аккаунт сохранён, прежняя access-cookie принимается без refresh.
- Второй экземпляр launcher отклоняется, не затрагивая первый.
- Занятый порт приводит к ошибке; работающий на нём процесс и PostgreSQL сохранены.
- Ctrl+C во время работы останавливает приложения и самостоятельно запущенную базу.
- Завершение API приводит к ошибке launcher и остановке фронтенда;
  ранее запущенная PostgreSQL остаётся работающей.
- Ctrl+C во время подготовки проверен с временным заменителем Go build:
  завершаются родительский и дочерний процессы, блокировка удаляется.
- `bash -n scripts/dev.sh` и `git diff --check` — успешно.
- Backend: check-sqlc, Go tests с изолированной PostgreSQL и HTTPS browser check,
  go vet и сборка — успешно, интеграционные сценарии не пропущены.
- Frontend: lint, typecheck, 28 unit/компонентных тестов и production-сборка — успешно.

Проверки launcher используют отдельный Compose project
`uptime-dev-smoke-20261006`; основной development volume не затрагивается.
macOS в текущем окружении не проверялась; скрипт использует переносимые средства
Bash и явное управление группами процессов.


### Исправление адреса из вывода Next dev — 2026-10-06

Next dev сообщает адрес listener `127.0.0.1:3000`, тогда как CORS и
SameSite=Lax cookies рассчитаны на `localhost`. При общем запуске скрипт
передаёт `LOCAL_DEV_LAUNCH=1`: Next временно перенаправляет запросы с
`127.0.0.1` на `http://localhost:3000`, сохраняя путь и query. Без этого флага
перенаправление отсутствует. Readiness проверяет и 307 на IP, и 200 на localhost.

Проверено в Chrome с отдельным Compose project: открытие корня по IP приводит
к рабочей странице входа на localhost; регистрация, переход на аккаунт по IP,
выход и повторный вход работают. Сохранение пути/query подтверждено HTTP-ответом.
