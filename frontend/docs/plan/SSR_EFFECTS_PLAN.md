# Серверная разметка и сокращение эффектов

## Решение

Сохранить прямую браузерную авторизацию через API и HttpOnly cookies.
Персональный SSR недоступен: cookies ограничены путями `/api/v1*` и хостом API,
поэтому не поступают в запросах страниц к Next.js. Не добавлять прокси,
Server Actions, серверные запросы авторизации или новое хранение токенов.

## Изменения

- Серверные страницы `/login` и `/register` сразу выводят заголовок и описание.
  Клиентская форма появляется после проверки сессии. Ссылка между формами
  передаётся через серверный слот `footer: ReactNode`.
- AuthProvider оборачивает только содержимое карточки; его экземпляр сохраняется
  при переходах между страницами.
- Account и AuthForm используют `redirect()` при рендере вместо эффектов
  навигации. Анонимный пользователь на `/account` переходит на `/login`,
  авторизованный на страницах форм — на `/account`, корень выбирает страницу
  по состоянию сессии. Переход заменяет запись истории. При загрузке и ошибке
  переходов нет.
- Единственный эффект AuthProvider управляет запуском сессии, BroadcastChannel
  и подписками focus/visibility с очисткой. useSyncExternalStore, refresh,
  Web Locks и обработка неопределённых POST сохраняются.
- Формы, ошибки и персональные данные остаются клиентскими. Динамический SSR
  не включается принудительно; статический HTML может быть сформирован при сборке.

## Приёмка

- Первоначальный HTML форм содержит заголовок, описание и проверку сессии,
  без полей и персональных данных.
- Проверить переходы, историю, ошибки и загрузку, очистку подписок в Strict Mode.
- Сохранить проверки валидации, ошибок и повторной отправки.
- Выполнить format:check, lint, typecheck, Vitest, production build и реальные
  Playwright E2E для localhost и отдельных HTTPS-сайтов, включая cookies,
  refresh, вкладки, сетевые сбои и восстановление. Осмотреть мобильные экраны.

## Результаты — 2026-10-06

- format:check, lint и typecheck прошли.
- Vitest: 40 тестов прошли, включая серверную разметку, переходы и Strict Mode.
- Production build с `NEXT_PUBLIC_API_URL=http://localhost:8080` прошёл:
  все страницы предварительно сформированы как статические. Turbopack завис
  внутри песочницы; повторная сборка вне неё завершилась успешно.
- Playwright с реальным Go API и PostgreSQL: 23 теста прошли на localhost
  и отдельных HTTPS-сайтах. Подтверждены первоначальный HTML без JavaScript,
  замена истории при регистрации и выходе, переходы по текущей сессии,
  синхронизация вкладок, refresh, сетевые ошибки и блокировка cookies.
- Осмотрены скриншоты первого экрана, формы входа и мобильного аккаунта;
  проблем с разметкой не обнаружено. Скриншоты находятся в игнорируемом
  `test-results/`.
- В исходниках остался один useEffect, в AuthProvider. Контракт API,
  cookies и хранение токенов не изменены. Количественное уменьшение размера
  клиентского JavaScript не измерялось.
