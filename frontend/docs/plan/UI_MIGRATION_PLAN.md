# Миграция UI на shadcn/ui и Tailwind CSS

## Решения

- shadcn/ui, Radix UI, стиль new-york, Tailwind CSS 4, React 19.
- Компоненты Button, Input, Label, Card, Alert, DropdownMenu хранятся локально.
- Постоянная тёмная тема: почти чёрный фон, лаймовые акценты,
  зелёно-жёлтые градиенты и тонкая сетка по референсу ui.png.
- Мигрируют вход, регистрация, аккаунт, пустой дашборд и состояния сессии.
- API, авторизация, маршруты и серверная разметка сохраняются.
- Светлая тема, навигация для будущих функций и мониторинг не входят в задачу.

## Реализация

Глобальный CSS содержит импорты, токены через @theme inline и базовый слой.
Оформление и адаптивность перенесены в Tailwind utilities. Общие элементы
страниц вынесены в PageShell, Surface, Brand, Eyebrow и PageHeading.
Для классов используется cn на clsx и tailwind-merge; для иконок — Lucide.

Меню пользователя заменено на DropdownMenu с доступным именем триггера,
клавиатурной навигацией, Escape и закрытием снаружи. Выход сохраняет меню
открытым на время запроса, блокирует повторное действие, показывает ошибку
на странице. Компонентные и E2E-проверки используют содержание и роли.

## Приёмка

- format:check, lint, typecheck, Vitest.
- Production build с NEXT_PUBLIC_API_URL.
- Полный Playwright E2E с реальным API, localhost и cross-site HTTPS.
- Меню: Enter, стрелки, Escape с возвратом фокуса, клик снаружи, выход.
- Все страницы на ширинах 375 и 1440 px; отсутствие горизонтального скролла,
  длинные имя/email, ошибки и pending-состояния.
- Скриншоты в test-results для просмотра и приложения к PR.

## Результаты проверки — 2026-10-06

- format:check, lint, typecheck и git diff --check — успешно.
- Vitest — 40 тестов успешно.
- Production build с NEXT_PUBLIC_API_URL=http://localhost:8080 — успешно.
- Playwright с BROWSER_EXECUTABLE=/usr/bin/google-chrome — 27 тестов успешно,
  включая localhost, cross-site HTTPS и блокировку сторонних cookies.
- Проверены длинные имя/email, ширины 375 и 1440 px, меню с клавиатуры,
  закрытие снаружи, pending-состояние и ошибка выхода.
- Просмотрены скриншоты входа, регистрации, аккаунта, меню и ошибки выхода;
  горизонтальный скролл отсутствует. Скриншоты находятся в test-results/.

Проверка выхода выявила, что Session очищает пользователя перед POST.
Dashboard и Account сохраняют пользователя локально только для собственного
запроса выхода и его ошибки. Успешный выход по-прежнему перенаправляет на вход;
явная повторная проверка убирает локальный экран ошибки и проверяет сессию.
Слой сессии и API не изменены.
