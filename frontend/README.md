# Frontend

Совместный запуск — `npm run dev` из корня репозитория;
см. [запуск и остановку](../README.md#запуск-всего-окружения).
Команды ниже выполняются из `frontend/`. Требуется Node.js 20.19+
(либо 22.12+ / 24+) и npm. Версии зависимостей смотрите в `package.json` и lockfile.

## Запуск и конфигурация

Для отдельного запуска сначала поднимите [API и БД](../backend/README.md#локальный-запуск):

```sh
npm ci
npm run dev
```

- Открывайте `http://localhost:3000`; не смешивайте `localhost` и `127.0.0.1`.
- Личные настройки записывайте в `.env.development.local`. Переменные и порты —
  в `.env.example`; общие локальные значения — в `.env.development` и `.env.test`.
- Приоритет: процесс → `.env.<среда>.local` → `.env.local` (кроме test) →
  `.env.<среда>` → `.env`. После изменения env перезапускайте приложение.
- `NEXT_PUBLIC_API_URL` обязателен: точный origin без пути, завершающего `/`,
  credentials, query или fragment. Значение публичное и подставляется при сборке;
  изменение адреса API требует новой сборки.
- Для отдельных HTTPS-сайтов согласуйте frontend origin с `ALLOWED_ORIGINS` API,
  задайте API `COOKIE_SECURE=true`, `COOKIE_SAME_SITE=none`.
- Для оптимизации аватаров сервер Next.js должен иметь сетевой доступ к API.
  Сохраняйте ограничение `remotePatterns` на origin API и `/api/v1/avatars/**`
  без query; не разрешайте произвольные хосты и редиректы.
- Не меняйте системные DNS и доверие сертификатам ради E2E: используйте
  `scripts/e2e-dns.mjs` и `NODE_EXTRA_CA_CERTS` только в тестовом процессе.

## Правила изменений

- Контракт запросов — в [README backend](../backend/README.md#http-контракт).
  Используйте `credentials: 'include'`, `cache: 'no-store'` и
  `X-CSRF-Protection: 1` для POST/PUT/DELETE.
- Не читайте, не декодируйте и не сохраняйте токены в браузерном коде;
  не формируйте `Authorization` или `Cookie`. Пользователя и мониторы
  не сохраняйте в browser storage. LocalStorage допустим для несекретного
  флага `uptime-auth-uncertain`.
- Изменения сессии сериализуйте через существующие Web Locks;
  BroadcastChannel должен передавать события без токенов и персональных данных.
  Координация действует только между вкладками одного frontend origin.
- Не повторяйте POST/PUT/DELETE автоматически после сетевой ошибки.
  Неизвестный результат refresh блокирует автоматические refresh до явного
  восстановления; неизвестный результат изменения монитора требует обновить список.
- Сетевая ошибка не означает выход. При `401` GET допускается одна повторная
  попытка после проверки сессии через существующую координацию refresh.
  Игнорируйте устаревшие ответы после смены пользователя.
- Не добавляйте персональный SSR без пересмотра авторизации: cookies API
  не поступают в запросах страниц Next.js. Проверку прав выполняет API.
  Страницы и layout сохраняйте серверными, формы и персональные данные — клиентскими.
- При ошибке формы сохраняйте черновик; во время сохранения блокируйте
  повторные и конфликтующие изменения. Для удаления требуйте явное подтверждение,
  первоначальный фокус ставьте на отмену; после закрытия возвращайте фокус.
- Интервал переводите в целое число секунд без округления; ограничения URL,
  профиля и файлов берите из backend-контракта. `204` не разбирайте как JSON.

## UI и оформление

- Используйте существующие shadcn/ui компоненты из `src/components/ui/`,
  Radix-вариант и стиль `new-york`. Для добавления:

```sh
npx shadcn@4.21.3 add <component>
```

- После генерации проверяйте diff и импорты; используйте `cn` из `@/lib/utils`,
  иконки из `lucide-react`. Не перезаписывайте настроенные компоненты без проверки.
- Сохраняйте тёмную тему. Палитру меняйте в `src/app/globals.css`,
  компоновку и состояния задавайте Tailwind-классами в компонентах;
  не добавляйте глобальные CSS-классы оформления. Общую оболочку берите из `page-shell.tsx`.
- Логотип для тёмного фона — `public/brand/logo.svg`, знак и favicon —
  `public/favicon.svg`; подключение favicon задаётся в metadata `src/app/layout.tsx`.
  При изменении знака обновляйте оба SVG; сохраняйте буквы логотипа контурами,
  чтобы файл не зависел от внешних шрифтов.
- Основной текст, формы и кнопки — `font-sans` (Manrope);
  короткие подписи, надзаголовки, футер, бейджи и email — `font-mono` (JetBrains Mono).
  При сборке нужен доступ к Google Fonts.
- Форматирование задаётся `.prettierrc.json`; не дублируйте его ручными правилами.
  После автоисправления ESLint запускайте Prettier:

```sh
npm run lint -- --fix
npm run format
```

- При смене корневого размера шрифта обновляйте `rootFontSize` в настройках
  `eslint-plugin-better-tailwindcss`; текущая настройка — 16.

## Проверки

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build:development
```

Для ручного осмотра сборки — `npm start`. Если sandbox запрещает Turbopack
открывать порт build workers, используйте `npm run build:development -- --webpack`.

Для изменений авторизации выполняйте реальные E2E; для UI осматривайте
мобильные и desktop скриншоты и прикладывайте их к PR:

```sh
npx playwright install chromium
npm run test:e2e
# Системный Chromium:
BROWSER_EXECUTABLE=/usr/bin/google-chrome npm run test:e2e
```

- Требуются Docker Compose, Go версии backend, OpenSSL и свободные порты
  55432, 13000, 13001, 13443, 13999, 18080, 18081, 18443.
- Runner использует `.env.test` обоих проектов, создаёт временную БД и запускает API.
  Не задавайте production URL или credentials. `.env.local` не используется для test;
  переменные процесса имеют приоритет. Не подменяйте успешные API-сценарии моками.
- Не запускайте параллельно Go integration tests: E2E управляет всем `postgres-test`
  и удаляет контейнер при завершении. Development volume сохраняется.
- При незавершённой очистке удалите тестовый контейнер из `backend/`:

```sh
docker compose --profile test rm --stop --force postgres-test
```

- Пропущенные реальные сценарии не считаются проверкой. Ошибки разбирайте,
  не маскируйте повторами. Скриншоты и диагностика — в `test-results/`;
  не коммитьте их, зависимости, сборки, сертификаты и env с секретами.
