# Uptime App

## Запуск всего окружения

Требуются Bash, Node.js 20.19+ (либо 22.12+ / 24+), npm, Go 1.27+,
Docker с Compose 2.24+, curl и OpenSSL. Docker daemon должен работать.
Из корня репозитория:

```sh
npm run dev
```

Корневые npm-зависимости устанавливать не нужно. Команда сама устанавливает
зависимости фронтенда при первом запуске или изменении manifest/lockfile,
поднимает PostgreSQL, применяет миграции, собирает Go API и запускает Next dev.
После сообщения о готовности откройте **http://localhost:3000**;
API доступен на **http://localhost:8080**. Порты 3000, 8080 и PostgreSQL 5432
должны быть доступны. При открытии `http://127.0.0.1:3000` браузер автоматически
перенаправляется на `localhost` с сохранением пути и query. Это обеспечивает
единый origin для CORS и cookies.
Приложения слушают только loopback.

Ctrl+C завершает приложения и останавливает PostgreSQL, если её запустила эта
команда. Ранее запущенный контейнер продолжает работать. Данные в Compose volume
сохраняются. Изменения фронтенда подхватываются автоматически; после изменения
Go-кода перезапустите команду. Повторный экземпляр команды отклоняется.

Настройки находятся в `backend/.env.development` и `frontend/.env.development`;
тестовые — в `.env.test` каждого проекта, полный образец — в `.env.example`.
Общие файлы содержат только локальные настройки и коммитируются.
При первом общем запуске JWT-секрет создаётся в игнорируемом
`backend/.env.development.local`.
Не пересоздавайте этот файл при каждом запуске.
Личные изменения помещайте в `.env.development.local` соответствующего проекта;
переменные процесса имеют больший приоритет. После изменения env перезапустите приложения.
При смене портов согласуйте `HTTP_ADDR`, `PORT`, `NEXT_PUBLIC_API_URL` и `ALLOWED_ORIGINS`.
Бинарники и служебные файлы остаются в игнорируемой `.dev/`.

Отдельное управление PostgreSQL из корня:

```sh
npm run db:up
npm run db:stop
```

`db:stop` явно останавливает development service `postgres`, сохраняя volume.
Команды используют `backend/compose.yaml` и поддерживают стандартную переменную
`COMPOSE_PROJECT_NAME`; по умолчанию проект Compose — `backend`. Смена project
name создаёт отдельный набор контейнеров и данных, но использует те же порты.

Проверка синтаксиса launcher: `bash -n scripts/dev.sh`.
